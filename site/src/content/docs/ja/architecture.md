---
title: アーキテクチャ
description: kozod、ワーカー、CLI、ダッシュボードの役割分担、状態の記録の仕方、タスクの進み方を説明します。
---

kozo は、1 台のマシンの上で、常駐するプロセス kozod を中心に動くいくつかのプロセスでできています。このページでは、その役割分担を説明します。kozo を使うのに必要ではありませんが、kozo がなぜそう振る舞うのかが分かります。

## プロセス

```text
 kozo (CLI) ──┐
              ├── local API (127.0.0.1:7420) ── kozod ──┬── worker ── claude session
 dashboard ───┘                                         ├── worker ── claude session
                                                        ├── commands in the command sandbox
                                                        └── gh, git (GitHub mode)
```

| プロセス       | 役割                                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| kozod          | コードで決められる判断をすべて行います。item の受け入れ、Charter に照らした計画の確認、タスクの確保、blueprint の実行、上限・backpressure・予算の適用、マージの追跡です。状態を書くのは、このプロセスだけです。 |
| ワーカー       | kozod の子プロセスで、1 つの worktree で 1 つのエージェントのセッションを動かします。すべてのツールの呼び出しの前に guard が入ります。書き込みとコミットは、自分の worktree の中でしか行いません。              |
| `kozo`         | local API の、状態を持たないクライアントです。準備と検証のコマンドも含みます。                                                                                                                                  |
| ダッシュボード | kozod が提供する、状態を持たないページで、同じ API のもう 1 つのクライアントです。                                                                                                                              |

モデルが担うのは、分類、計画の下書き、実装、レビューです。ほかのことはすべて kozod が決定的に決めます。そのため、同じ Charter のもとでは、同じ依頼はいつも同じように振り分けられ、制限され、確かめられます。

## 層

| 層   | 担うもの                                                                              | 場所                                               |
| ---- | ------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 制御 | stage の振り分け、計画と Charter の確認、タスクの確保、backpressure と予算。          | kozod                                              |
| 実行 | worktree でのエージェントのセッション。                                               | ワーカー                                           |
| 検証 | 決定的な確認（gate、diff-guard、prove）と、別のセッションの判定役（review、verify）。 | kozod。コマンドの sandbox と判定役のセッションの中 |
| 記録 | run ごとの event log、指示のキュー、それらから作る SQLite のインデックス。            | `~/.kozo`                                          |

## 状態は event log

kozo が知っていることは、すべて追記だけの event log にあります。ファクトリーに 1 つ、run ごとに 1 つです。各行にはバージョンがあり、前の行とつながっていて、run が終わるとログに封をします。kozod は起動のたびに、ログから状態と `kozo.db` のインデックスを作り直します。封をしたログが変わっていれば、起動しません。

そのため、クラッシュしても記録済みのものは失われず、`kozo admin db-rebuild` でいつでもインデックスを作り直せます。ログを手で編集してはいけないのも、このためです。

local API を通した書き込みは、それぞれ固有の ID を持つ 1 回の API 呼び出しで、それが起こす event はすべてその ID を持ちます。

## タスクの進み方

blueprint は、1 つのタスクを Building から Handoff まで進める、決まった並びのノードです。決定的なノードは kozod が自分で実行し、エージェントのノードはワーカーでモデルを動かします。

| ノード               | 種類         | 起きること                                                                                                                           |
| -------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| claim                | 決定的       | 最新のデフォルトブランチから、タスクブランチと worktree を作ります。ブランチを作ることが、タスクの確保になります。                   |
| prepare              | 決定的       | services を起動し、ポートを選び、worktree ごとに 1 回 prepare を実行します。                                                         |
| brief                | 決定的       | 計画から決まった形式の指示（brief）を書きます。依頼は信頼できないデータとして入れます。                                              |
| implement            | エージェント | implement エージェントが、タスクの scope の中でコードを変えてコミットします。計画に codemod があれば、先にそれを実行します。         |
| verify-deterministic | 決定的       | risk tier の水準の gate、prove、diff-guard を実行します。                                                                            |
| review               | エージェント | 別のセッションの判定役が、差分、目的、完了の条件だけを読みます。                                                                     |
| verify-app           | エージェント | risk tier が low でなければ、verify エージェントが `.kozo/verify-app.md` の手順でアプリを動かし、証拠を残します。                    |
| handoff              | 決定的       | handoff report を書きます。                                                                                                          |
| final-verify         | 決定的       | 最新のデフォルトブランチに rebase して deep の gate を実行します。これを通ってはじめて、タスクがあなたのマージを待つ状態になります。 |

kozod は、タスクが各ノードに入るたびにチェックポイントを記録するので、止まった run や失った run はそこから続きます。確認に失敗すると、何が失敗したかを添えて、Charter の上限の範囲でタスクを戻します。上限を超えると、タスクはあなたを待ちます。

## エージェント

| エージェント | セッション                           | 仕事                                                                                                                                           |
| ------------ | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| triage       | リポジトリを読むだけで、何も書かない | 計画を下書きします。work class、risk tier、方針、完了の条件、タスクです。                                                                      |
| plan         | リポジトリを読むだけで、何も書かない | 差し戻しや回答のあとに計画を書き直します。feature では受け入れ条件をあなたと詰め、scope の中で終わらないタスクがあれば作業を切り分け直します。 |
| implement    | worktree で作業する                  | タスクを 1 つ実装します。                                                                                                                      |
| review       | ツールを持たない判定役               | 差分を判定します。accept、revise、escalate のいずれかです。                                                                                    |
| verify       | シェルだけ                           | アプリを操作し、完了の条件を 1 つずつ確かめます。                                                                                              |
| explorer     | ツールを持たない判定役               | `kozo say --ask` に、記録をもとに答えます。                                                                                                    |

どのエージェントも、Agent SDK 経由か `claude -p` として、あなた自身の `claude` で動き、指示は factory definition から受け取ります。
