title: ダッシュボード
description: ダッシュボードを開き、inbox を片付け、board で作業を追い、詳細画面から item、task、run を操作します。
---

ダッシュボードは、kozod が提供するローカルの Web ページです。`kozo` と同じ状態を表示し、同じ local API を呼ぶので、どちらで操作しても、もう一方に反映されます。ダッシュボード自身は状態を持ちません。

このページのラベルは、`factory.yml` の `locale` が `ja` のときの表示です。`en` では英語で表示されます（**開始を承認** なら **Approve start**）。

## 開く

```sh
kozo dashboard
```

ブラウザで `http://127.0.0.1:7420/` を開きます。アドレスには使い捨てのコードが付いていて、ページはこれをそのタブのセッションと引き換え、すぐにアドレスから消します。コードは 1 回しか使えず、有効なのは 1 分です。`kozo dashboard --url` は、開く代わりにアドレスを表示します。

- **セッションはタブごとです。** 新しいタブには開き方が表示されるので、もう一度 `kozo dashboard` を実行します。
- **セッションは使っている間は続きます。** 24 時間リクエストがないとき、または kozod が起動し直したときに終わります。終わるとページにそう表示されるので、同じ方法で開き直します。
- **kozod が応答しないとき**は、ヘッダーの下に、どの時点の状態を表示しているかを示すバナーが出ます。ページは数秒ごとに再接続を試み、**今すぐ試す** ですぐに試せます。
- **API token はブラウザに渡りません。** kozod がページのリクエストをどう守っているかは、[安全の仕組み](../security/#local-api) で説明しています。

ページは、表示されている間 3 秒ごとに更新します。詳細画面の event は、起きたそばから流れてきます。

## ヘッダー

ヘッダーには、待っているものの数を添えた **対応待ち** と、**ボード** へのリンクがあります。その横に、ファクトリーの状態が並びます。

- **稼働中** か **停止中**。止めているときはその理由。
- いま動いている run の数。開くと、各 run と、そのエージェント、作業対象が並びます。
- 今日の費用と、モード（`local` か `github`）。
- **ファクトリーを止める** か **ファクトリーを再開する**。ファクトリーを止めている間は新しい作業を始めず、動いている run は最後まで続きます。

## Inbox

inbox は、あなたを待っているものを古い順に並べたもので、`kozo ls` の出力と同じです。各行には、待っている理由、タイトル、reference、待っている時間を表示します。kozo が複数のリポジトリで作業しているときは、リポジトリも表示します。

| 行         | 操作                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 開始の承認 | **開始を承認**、**取り消す**                                                    |
| 計画の承認 | item を開く **計画を読む**、続いて **計画を承認** と **計画を差し戻す**         |
| 質問       | **回答**。タスクなら **自分で作業する** も                                      |
| attention  | **やり直す**、タスクなら **自分で作業する**、**完了として閉じる**、**取り消す** |
| マージ待ち | タスクを開く **差分を読む**                                                     |

- **承認、回答、差し戻し、やり直し、指示、返却の操作は、先に入力を求めます。** ボタンの代わりに入力欄が開き、Cmd+Enter か Ctrl+Enter で送ります。Escape か **戻る** で閉じます。回答や、計画を差し戻す理由のように、操作に欠かせない入力は省けません。
- **閉じる操作は、ダイアログで確かめます。** **取り消す** は、item や task と一緒に消えるもの（run、worktree、ブランチ）を示し、理由を尋ねます。**完了として閉じる** は、Complete として閉じることを示します。
- **片付いた行は inbox から消えます。** フォーカスは次の行の最初の操作に移るので、キーボードだけで上から順に片付けられます。
- **マージのボタンはありません。** マージは、git か GitHub であなたが行います。

## Board

board は、すべての item を、**タスク** に切り替えればすべての task を、stage ごとの列にカードで並べます。列は受付（Intake）、トリアージ（Triage）、計画（Planning）、実装（Building）、レビュー（Reviewing）、引き渡し（Handoff）、完了（Complete）、取り消し（Cancelled）です。表示はアドレスに残るので、リンクを開くと同じ表示になります。

- item のカードには、reference、自律度、タイトル、hold、work class と、タスクのうち完了したもの、止まっているもの、マージ待ちのものの数を表示します。
- task のカードには、reference、目的、hold、マージ待ちかどうか、review が求めた修正の回数を表示します。
- 完了と取り消しの列は、件数だけに畳んであります。開くと、新しいほうから 10 枚を表示します。
- item のカードの矢印は、kozod が作業を始める順番を 1 つ上か下に動かします。`kozo reorder` と同じ操作です。
- local モードでは、**新規 item** でダイアログが開きます。入力するのは、タイトル、依頼、リポジトリ（複数あるとき）、work class です。work class を選ばなければ triage が決めます。ダイアログを閉じても、item を追加するまでは入力した内容が残ります。

## 詳細画面

reference を選ぶと、対応待ちやボードの横にペインが開き、詳細画面を表示します。ペインを開いたままでも、一覧は操作できます。狭い画面では、ペインは下から出ます。アドレスには一覧と reference の両方が入るので、リンクを開くと同じ組み合わせで表示されます。ペインに表示している行やカードには印が付きます。Escape か閉じるボタンでペインを閉じると、その行やカードに戻ります。

タイトルの上には、item から task、run へのたどり方が表示されます。ペインの下端は、本文をスクロールしても動きません。読み終えたその場で操作できます。

- **待っている理由が最初にあります。** 質問の内容や、要対応になった理由です。
- **入力欄は最初から開いています。** 文字を受け取る操作はこの 1 つの欄を共有し、欄にはそれぞれの操作が何を受け取るかが表示されます。**回答** や **計画を差し戻す** のように文字が必要な操作は、入力するまで押せません。Cmd+Enter か Ctrl+Enter で、先頭の操作を送ります。
- **書きかけの文字は残ります。** ペインで別の reference を表示しても、送るまで消えません。
- **完了として閉じる** と **取り消す** は **その他** の中にあり、ダイアログで確認してから実行します。task が問題なく進んでいるときは、**自分で作業する** もここにあります。

### item

item の画面は、書かれたままの依頼から始まります。続いて計画で、承認待ちなら下書きの計画、承認済みなら採用された計画です。どちらも、方針、完了の条件、タスクを表示します。最後にタスクの一覧が続きます。

### task

マージ待ちのタスクの画面は、マージに要るものから始まります。ブランチ、マージ先、リポジトリ、ブランチ名をコピーするボタン、handoff report、それに最初から開いた差分です。その下に、run report、review の判定と指摘、verify の判定と証拠、完了の条件、タスクが従った blueprint、エージェントの decision log が続きます。

作業中のタスクも同じ区画を表示しますが、完了の条件から始まり、差分は最後です。差分は **差分を表示** で読み込みます。長い差分は途中で切れるので、全体は `kozo show --diff` で見ます。

| 状態         | 操作                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 作業中       | **指示**（動いている run には次のターンで届き、以降の run にも渡ります）、**止める** |
| 質問         | **回答**、**自分で作業する**、**取り消す**                                           |
| attention    | **やり直す**、**指示**、**自分で作業する**、**完了として閉じる**、**取り消す**       |
| 自分で作業中 | 作業をコミットしてから **kozo に返す**、**取り消す**                                 |

詳細画面の止めるは、`kozo pause --now` と同じく、作業をすぐに止めます。

### run

run の画面には、エージェント、モデル、開始と終了の時刻、費用を表示します。動いている間は、**指示** と **止める** が、その run の task か item に働きます。

### event とプロパティ

どの詳細画面も、最後に event を新しい順に、run ごとにまとめて表示します。本文の横のプロパティには、item なら、リポジトリ、class、risk tier、自律度を、task なら、scope、依存先、ブランチを表示します。費用と run の一覧は、どちらにも表示します。

## CLI でしかできないこと

日々の作業はダッシュボードで足ります。次の操作だけは、コマンドラインで行います。

- 作業について explorer に尋ねる: `kozo say --ask`。
- item を GitHub の Issue に移す: `kozo issue`。
- item を任意の位置まで一度に動かす: `kozo reorder --before`。
- item や task を、すぐにではなく次のノードで止める: `--now` なしの `kozo pause`。
- レポート、準備、保守: `kozo report`、`kozo check`、`kozo admin`。
