---
title: ダッシュボード
description: ダッシュボードを開き、inbox を片付け、board で作業を追い、詳細画面から item、task、run を操作します。
---

ダッシュボードは、kozod が提供するローカルの Web ページです。`kozo` と同じ状態を表示し、同じ local API を呼ぶので、どちらで操作しても、もう一方に反映されます。ダッシュボード自身は状態を持ちません。

## 開く

```sh
kozo dashboard
```

ブラウザで `http://127.0.0.1:7420/` を開きます。アドレスには使い捨てのコードが付いていて、ページはこれをそのタブのセッションと引き換え、すぐにアドレスから消します。コードは 1 度だけ、1 分以内に使えます。`kozo dashboard --url` は、開く代わりにアドレスを表示します。

- **セッションはタブごとです。** 新しいタブには開き方が表示されるので、もう一度 `kozo dashboard` を実行します。
- **セッションは使っている間は続きます。** 24 時間リクエストがないとき、または kozod が起動し直したときに終わります。終わるとページにそう表示されるので、同じ方法で開き直します。
- **kozod が応答しないとき**は、ヘッダーの下に、いつ時点の状態を表示しているかがバナーで出ます。ページは数秒ごとに再接続を試み、**Try now** ですぐに試せます。
- **API token はブラウザに渡りません。** kozod は `127.0.0.1` でだけ待ち受け、自分のポートの `127.0.0.1` か `localhost` 宛てのリクエストにしか応答しません。

ページは、表示されている間 3 秒ごとに更新します。詳細画面の event は、起きたそばから流れてきます。

## ヘッダー

ヘッダーには、待っているものの数を添えた **Inbox** と、**Board** へのリンクがあります。その横に、ファクトリーの状態が並びます。

- **Running** か **Paused**。止めているときはその理由。
- いま動いている run の数。開くと、各 run と、そのエージェント、作業対象が並びます。
- 今日の費用と、モード（`local` か `github`）。
- **Pause factory** か **Resume factory**。ファクトリーを止めている間は新しい作業を始めず、動いている run は最後まで続きます。

## Inbox

inbox は、あなたを待っているものを古い順に並べたもので、`kozo ls` の出力と同じです。各行には、待っている理由、タイトル、reference、待っている時間を表示します。kozo が複数のリポジトリで作業しているときは、リポジトリも表示します。

| 行         | 動詞                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 開始の承認 | **Approve start…**、**Cancel…**                                             |
| 計画の承認 | item を開く **Read the plan**、続いて **Approve plan…** と **Reject plan…** |
| 質問       | **Answer…**。タスクなら **Take it over** も                                 |
| attention  | **Retry…**、タスクなら **Take it over**、**Close as done…**、**Cancel…**    |
| マージ待ち | タスクを開く **Read the diff**                                              |

- **ラベルが「…」で終わる動詞は、先に入力を求めます。** ボタンの代わりに入力欄が開き、Cmd+Enter か Ctrl+Enter で送ります。Escape か **Back** で閉じます。回答や計画を差し戻す理由など、動詞に要るときは入力が必須です。
- **閉じる動詞は、ダイアログで確かめます。** **Cancel…** は、item や task と一緒に消えるもの（run、worktree、ブランチ）を示し、理由を尋ねます。**Close as done…** は、Complete として閉じることを示します。
- **片付いた行は inbox から消えます。** フォーカスは次の行の最初の動詞に移るので、キーボードだけで上から順に片付けられます。
- **マージのボタンはありません。** マージは、git か GitHub であなたが行います。

## Board

board は、すべての item を、**Tasks** に切り替えればすべての task を、stage ごとの列にカードで並べます。列は Intake から Cancelled までです。表示はアドレスに残るので、リンクを開くと同じ表示になります。

- item のカードには、reference、自律度、タイトル、hold、work class と、タスクのうち完了したもの、止まっているもの、マージ待ちのものの数を表示します。
- task のカードには、reference、目的、hold、マージ待ちかどうか、review が求めた修正の回数を表示します。
- Complete と Cancelled の列は、件数だけに畳んであります。開くと、新しいほうから 10 枚を表示します。
- item のカードの矢印は、kozod が作業を始める順番を 1 つ上か下に動かします。`kozo reorder` と同じ操作です。
- local モードでは、**New item** でダイアログが開きます。入力するのは、タイトル、依頼、リポジトリ（複数あるとき）、work class です。work class を選ばなければ triage が決めます。ダイアログを閉じても、item を追加するまでは入力した内容が残ります。

## 詳細画面

reference を選ぶと、その詳細画面が開きます。タイトルの上には、item から task、run へのたどり方が表示されます。動詞はタイトルの下、hold の理由のあとに並びます。Pause、Take it over、Close as done、Cancel のようにあまり使わないものは、**More** の中にあります。

### item

item の画面は、書かれたままの依頼から始まります。続いて計画で、承認待ちなら下書きの計画、承認済みなら採用された計画です。どちらも、方針、完了の条件、タスクを表示します。最後にタスクの一覧が続きます。

### task

マージ待ちのタスクの画面は、マージに要るものから始まります。ブランチ、マージ先、リポジトリ、ブランチ名をコピーするボタン、handoff report、それに最初から開いた差分です。その下に、run report、review の判定と指摘、verify の判定と証拠、完了の条件、タスクが従った blueprint、エージェントの decision log が続きます。

作業中のタスクも同じ区画を表示しますが、完了の条件から始まり、差分は最後です。差分は **Show the diff** で読み込みます。長い差分は途中で切れるので、全体は `kozo show --diff` で見ます。

| 状態       | 動詞                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------- |
| 作業中     | **Instruct…**（動いている run には次のターンで届き、以降の run にも渡ります）、**Pause** |
| 質問       | **Answer…**、**Take it over**、**Cancel…**                                               |
| attention  | **Retry…**、**Instruct…**、**Take it over**、**Close as done…**、**Cancel…**             |
| 引き取り中 | 作業をコミットしてから **Give it back…**、**Cancel…**                                    |

詳細画面の Pause は、`kozo pause --now` と同じく、作業をすぐに止めます。

### run

run の画面には、エージェント、モデル、開始と終了の時刻、費用を表示します。動いている間は、**Instruct…** と **Pause** が、その run の task か item に働きます。

### event とプロパティ

どの詳細画面も、最後に event を新しい順に、run ごとにまとめて表示します。本文の横のプロパティには、item なら、リポジトリ、class、risk tier、自律度を、task なら、scope、依存先、ブランチを表示します。費用と run の一覧は、どちらにも表示します。

## CLI でしかできないこと

日々の作業はダッシュボードで足ります。次の操作だけは、コマンドラインで行います。

- 作業について explorer に尋ねる: `kozo say --ask`。
- item を GitHub の Issue に移す: `kozo issue`。
- item を任意の位置まで一度に動かす: `kozo reorder --before`。
- item や task を、すぐにではなく次のノードで止める: `--now` なしの `kozo pause`。
- レポート、準備、保守: `kozo report`、`kozo check`、`kozo admin`。
