kozo は、エージェントとリポジトリのコマンドを、人が見ていないところで動かします。使うのは、あなたのマシンと、あなた自身の `claude` です。エージェントが何を書いても、依頼に何が書かれていても、次の 3 つが守られるように作られています。

- **マージはいつも人が行います。** kozo には、マージする機能がありません。
- **エージェントとコマンドは、タスクの worktree の中にとどまります。** 認証情報を持たず、このマシン以外のホストには接続できません。
- **外に働きかけるのは kozod だけです。** タスクを push して pull request を開くのは kozod で、すべての確認を通ったあとに限ります。ほかに kozod が開く pull request は、`kozo admin install` を実行したときに kozo のファイルを足すものだけです。

## エージェントを囲む 2 つの層

エージェントのツールの呼び出しは、実行される前に 2 つの確認を通ります。

### guard

kozo の guard は、Claude Code が実行する前に、ワーカーの中でツールの呼び出しを 1 つずつ判定します。

- **ファイルのツール**が読み書きできるのは worktree の中だけです。`.git` の下には触れられず、シンボリックリンクやハードリンクのあるファイルも経由できません。
- **書き込み**は、タスクの scope の外、保護されたパス、そして Charter が守っているなら既存のテストに対しては拒まれます。triage と plan のセッションは何も書きません。
- **シェルのコマンド**は、`sh -c`、`eval`、worktree の中のスクリプトなどを通して、実行されるすべてのコマンドに分解されます。guard が拒むのは次のものです。
  - バックグラウンドのジョブ。
  - `gh`、`ssh`、`docker`、`sudo`、`open`、`osascript`、`crontab`、`kozo` 自身。
  - git の `push`、`pull`、`fetch`、`merge`、ブランチの切り替え、設定の変更、一覧にないサブコマンド。
- **ほかのツール**は拒まれます。例外は kozo 自身のツールで、判断の記録、質問、gate の実行です。

### Claude Code の sandbox

各セッションは Claude Code の sandbox を有効にして動き、sandbox を使えないときは動かずに失敗します。

- **ネットワーク**は、`localhost` と `127.0.0.1` にしか接続できません。
- **読み取り**は、`~/.kozo` と認証情報のパスが拒まれます。
- **書き込み**は、worktree と kozo 自身のブランチにだけ許されます。保護されたパス、既存のテスト、ほかのすべてのブランチ、タグ、`HEAD`、git の設定とフックへの書き込みは拒まれます。

セッションは、あなたの Claude Code の設定や記憶を読み込まず、記録も残しません。環境に入っているのは `claude` のサインインに要るものだけで、シェルからはそれも消されます。

kozod は、run のたびに、その run が worktree に残したプロセスを止めます。タスクのブランチ以外の git の ref が動いていれば、タスクをあなたの対応待ちにします。

## コマンドの sandbox

リポジトリ自身のコマンド（prepare、gate、prove、codemod）は、kozo のコマンドの sandbox の中で動きます。macOS では `sandbox-exec` による Seatbelt、Linux では bubblewrap です。kozod は、これを使えない環境では起動しません。

|              | 許すもの                                                                                                | 拒むもの                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 読み取り     | システム、worktree とその git のディレクトリ、パッケージのキャッシュ、`PATH` 上のツールとその設定       | ホームディレクトリのほかの部分、`~/.kozo`、`~/.ssh`・`~/.aws`・`~/.config/gh`・`~/.npmrc`・`~/.netrc`・`~/.claude`・キーチェーンなどの認証情報 |
| 書き込み     | `.git` を除く worktree と、コマンドごとの一時ディレクトリ。prepare はパッケージのキャッシュにも書けます | それ以外のすべて                                                                                                                               |
| ネットワーク | このマシンだけ。worktree のポートには接続でき、kozod の API には接続できません                          | ほかのすべてのホスト                                                                                                                           |

ほかのホストに接続できるのは `prepare` だけで、それも `127.0.0.1` にある kozod の egress proxy 経由に限ります。プロキシが HTTPS を通すのは、パッケージのレジストリ（npm、Yarn、PyPI、crates.io、Go のプロキシ、GitHub のダウンロード、Playwright のブラウザ）と、`prepare_hosts` のホストだけです。ほかは拒み、拒んだホストをそれぞれ 1 回報告します。

`services` と `teardown` は、コンテナのように sandbox では起動できないものを起動するので、sandbox の外で、デフォルトブランチから実行します。これらを変えられるのは人だけで、デフォルトブランチの constraints を通して変えます。

## 依頼はデータとして扱う

依頼の本文、Issue の文章、GitHub での返信、失敗した確認の出力は、指示ではなく信頼できないデータ（`<request trust="untrusted">`）としてエージェントに渡します。review が読む差分と、explorer が読む記録も、同じように包んで渡します。

GitHub モードでは、承認も信頼で決まります。リポジトリに書き込めない人の Issue は、どの自律度でも開始と計画の承認が要り、質問への回答として受け取るのは書き込める人の返信だけです。kozod が書くコメントでは、人へのメンションも Issue を閉じるキーワードも効きません。[GitHub モード](../github-mode/#コメント) を参照してください。

## 人だけが変えられるもの

次のものは、エージェントがあなたに尋ねずに変えることはありません。変える差分は diff-guard が質問に変え、それに届く計画にはいつもあなたの承認が要るからです。

- Charter の保護されたパス。既定では `.kozo/`、`.github/`、`.claude/`、`AGENTS.md`、`CLAUDE.md` です。
- `existing_tests_protected` が有効なときの、既存のテスト。

Charter と constraints は、確認しようとしている差分からではなく、デフォルトブランチから読みます。そのため、変更が自分を確かめる規則を緩めることはできません。

## push と GitHub

push するのは kozod だけです。対象は、最新のデフォルトブランチに rebase したあとの最後の確認を通った head だけで、送り先はタスクのブランチだけ、`--force-with-lease` を付けます。kozod は、あなたがサインインしたアカウントの `gh` を通して GitHub に触れます。決まった一覧にない gh のコマンドは拒み、その一覧には、マージ、リポジトリの設定の変更、自由な API の呼び出しが入っていません。ワーカーからは、サインインは見えません。ほかに kozod が push するのは GitHub モードの `kozo admin install` だけで、kozo のファイルを `kozo/<factory ID>/install` に push し、あなたが pull request として確かめます。[GitHub モード](../github-mode/#kozod-が-github-でできること) を参照してください。

## local API

kozod の API は `127.0.0.1:7420` でだけ待ち受け、公開のポートは開きません。

- **どのリクエストにも token が要ります。** `~/.kozo/api.token` の API token か、ダッシュボードのセッションです。kozod は API token を、あなただけが読める状態で作り、ほかの人が読めるときは使いません。
- **リクエストの Host は、kozod のポートの `127.0.0.1` か `localhost` でなければなりません。** Origin を伴う書き込みも、同じところから来たものに限ります。
- **CORS のヘッダーは一切送りません。**
- **ダッシュボードのセッションは、使い捨てのコードから始まります。** コードを求められるのは API token だけで、有効なのは 1 分です。セッションは使っている間続き、その kozod のプロセスでだけ有効です。

## kozo が守れないもの

- `services` と `teardown` のコマンドは、書かれたとおり sandbox の外で動きます。
- エージェントは worktree 全体を読めます。リポジトリにコミットされた秘密も含みます。
- `gh` がサインインしたアカウントは、そのアカウントに許されたことをすべてできます。kozod が制限しているのは、自分が実行するコマンドだけです。
- review と確認は、悪い差分の危険を減らします。最後の確認は、マージする前にあなたが差分を読むことです。
