# Decisions

> **Rules** (read before editing)
> - One decision per line: `- **D-NNN** (YYYY-MM-DD, Status) decision`. **Append only, at the end**
> - The status is `Proposed`, `Accepted` or `Superseded by D-NNN`
> - Never rewrite or delete an existing line. Only the status may change
> - To overturn a decision, append a new line and change the old line's status to `Superseded by D-NNN`
> - Numbers are consecutive with no gaps. Never renumber
> - **Don't write reasons, rejected options or impact.** Put them in the commit message with a `Decision: D-NNN` trailer,
>   and look up the history with `git log --grep='Decision: D-NNN'`
> - Write: choices of language, framework, database and external services / the shape of public APIs and the data model / authentication and authorization /
>   error handling and retry policy / directory layout principles / **options deliberately not adopted**
> - Don't write: variable names / changes confined to one file that can be reverted at any time / patch version updates
>
> **Split signals** (if any applies, split into `docs/decisions/`; the procedure is in AGENTS.md):
> more than 200 decisions / more than 1000 lines excluding the rules / more than 20 superseded decisions
