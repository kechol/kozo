# @kozo/core

## 0.1.0

### Minor Changes

- [`a340b25`](https://github.com/kechol/kozo/commit/a340b250b38266633bcf60e6a9c47f1cc6d93a31) Thanks [@kechol](https://github.com/kechol)! - Eval cases: `kozo admin eval add <run>` drafts the eval case of a run's item, its repository, start commit, request and the outcome it reached, into the factory definition's `evals/` for you to finish with hidden tests and checks and commit. `kozo admin eval run [<case>...]` runs the cases, or the named ones, each in a throwaway factory home on a clone of its repository at its start, approving every start and plan and merging every handoff, then lays a complete case's hidden tests over the result and runs its prepare and checks in kozo's sandbox; it prints each case's outcome, what a human must still check by hand, the share that reached the expected outcome and the cost, which is outside the factory's daily budget. A case that names an upstream issue reads its body with gh and refuses it when the body changed since the case was made.

- [`3cfce8e`](https://github.com/kechol/kozo/commit/3cfce8e48807fd4cc1276696be4c5a94f4bf348e) Thanks [@kechol](https://github.com/kechol)! - `kozo admin prune --older-than <days>` has kozod remove all but the event log, report, verdicts and decision log of every run whose item reached Complete or Cancelled at least that many days ago, and record the runs it pruned as `factory.pruned`; `--dry-run` lists them without removing anything. kozod prunes nothing on its own, and every event log stays, so `kozo admin db-rebuild` still works.

- [`b03a8d5`](https://github.com/kechol/kozo/commit/b03a8d578467aa31bc3da6bc480af288497c37ce) Thanks [@kechol](https://github.com/kechol)! - In a repository whose locale is not English, the agents write their summaries, questions, findings, notes and plans in that language, keeping JSON keys, enum values, paths, code and the conditions kozo gave them as they are; the explorer answers in the factory's locale.

- [`16dc8f2`](https://github.com/kechol/kozo/commit/16dc8f2296addd2c62d63084a3af3ec5aae38033) Thanks [@kechol](https://github.com/kechol)! - `kozo` prints its usage, its own output and its errors, `kozo check` included, in the factory's `locale`; the `KOZO_*` lines and `--json` keep their form.

- [`77cbf8a`](https://github.com/kechol/kozo/commit/77cbf8aa890d5cf0a70b7f62f4c0a43667d6cc95) Thanks [@kechol](https://github.com/kechol)! - The dashboard has a board: one column per stage, showing items or tasks. An item's card shows its hold, its work class, its autonomy level and how many of its tasks are complete or held; a task's card shows its hold and revisions. In local mode the board adds items as `kozo add` does, and the arrows on an open item's card move it up or down.
  
  Items now have an order in which kozod starts their work, the order they arrived in until you move one: `kozo reorder <item> [--before <item>]` moves an item before another, or to the end, and appends `item.reordered`. Triage, planning and every task's runs start in item order, and an item's tasks in plan order; a merged task's check still comes first. `kozo ls items` lists items in this order, each open one with the class and level it runs at.

- [`a88e830`](https://github.com/kechol/kozo/commit/a88e830fdbac768b59c026a0a72d1fecaa94b433) Thanks [@kechol](https://github.com/kechol)! - `.kozo/constraints.yml` may list `teardown`, commands that stop what `services` started. After each eval case, kozod runs the teardown of the repository's default branch in the case's clone and in each of its task worktrees, each first reset to the case's start without its untracked files, so that nothing the eval merged unread runs outside the sandbox.

- [`d32539e`](https://github.com/kechol/kozo/commit/d32539e0be94f8bf833b8b77e93467e8d665d7bb) Thanks [@kechol](https://github.com/kechol)! - The guard records why it refused a tool call as a message, shown in the factory's `locale` among a run's events; the agent still reads the refusal in English.

- [`e7b3d4d`](https://github.com/kechol/kozo/commit/e7b3d4dda39a585499f4bdca70c68c1f69206b7d) Thanks [@kechol](https://github.com/kechol)! - `kozo issue <item>` moves a local item that has no tasks yet to GitHub in GitHub mode: kozod opens an Issue in the item's repository with its title and request, adds the repository's intake label, and cancels the local item, naming the Issue; its next poll takes the Issue up as an item. kozod's gh wrapper allows `gh issue create` only in that form.

- [`668b47f`](https://github.com/kechol/kozo/commit/668b47fdb74edb76d82c8a0a2487c113d64d787f) Thanks [@kechol](https://github.com/kechol)! - `factory.yml` takes `locale`, `en` by default or `ja`, and kozod sends its notifications in that language.

- [`3fc1ef1`](https://github.com/kechol/kozo/commit/3fc1ef1171c2ed495f80347c1a7ebaa0f6079d45) Thanks [@kechol](https://github.com/kechol)! - The Charter's `isolation` accepts only `worktree`, and a blueprint lists every node, `verify-app` included: `isolation: docker` and a blueprint without `verify-app` changed nothing, since verify runs as the risk tier decides. A factory definition whose `blueprints/docs.yml` came from an earlier template needs `verify-app` added after `review`.

- [`8dbe593`](https://github.com/kechol/kozo/commit/8dbe59387666a18f3e8f7b0778b142b263d42e5f) Thanks [@kechol](https://github.com/kechol)! - `kozo say --ask <ref> <question>` answers a question about an item, a task or a run without touching the work. kozod gives the explorer agent, a session without tools, the question and its records as untrusted data: the request, the plan or the draft waiting for approval, every task's stage and hold, the subject's last 60 events, and for a task its run reports, decision logs and diff stat. The session is an explorer run of its own with its cost recorded, and kozod refuses an ask while the daily budget is spent. The factory definition may override the explorer's instructions and model in `agents/explorer/agent.md`; kozo's template has one.

- [`e469940`](https://github.com/kechol/kozo/commit/e46994044c0149c6a7b81b4bb0939a667814e391) Thanks [@kechol](https://github.com/kechol)! - `kozo take <task>` hands a task to you: kozod stops its session, holds it with `taken`, which only `kozo return` clears, in place of a question or attention hold, and prints its worktree and branch. Commit your work there, then run `kozo return <task> <what you changed and checked>`: kozod records the text as an instruction, appends `task.returned`, moves the task to Building and starts its next run at the deterministic checks, so your commits go through the gates, prove, diff-guard, review and verify. `kozo return` refuses while the worktree has uncommitted changes, and a task waiting on approval, a dependency or capacity cannot be taken. `kozo resume` and `kozo retry` refuse a taken task.

- [`4586e42`](https://github.com/kechol/kozo/commit/4586e42b619cbae3ab347297976d90c9da73261e) Thanks [@kechol](https://github.com/kechol)! - `kozo check`, the local API's validation errors and the hold of a refused plan draft word their issues in the factory's `locale`, both kozo's own and the schema library's; the plan agent still reads them in English.

- [`6894842`](https://github.com/kechol/kozo/commit/6894842a4e91f4228d15adfa1cb5cedc62194e2c) Thanks [@kechol](https://github.com/kechol)! - The implement agent runs its gates with the `kozo_gates` tool instead of `kozo gates` in its shell. The worker runs them in the task's command sandbox, the one `kozod`'s own gates use, so browser tests and the deep gates run during the session. Stop-check accepts only a pass at the brief's level on the agent's last commit with nothing left uncommitted, and the guard refuses `kozo` in the agent's shell. The worker spec is version 2.

- [`04fed38`](https://github.com/kechol/kozo/commit/04fed38e9338a87f9f6da86da4f734c8971fe80e) Thanks [@kechol](https://github.com/kechol)! - The local API answers every verb and reports every error in the factory's `locale`, with the message's `code` and `values` beside the sentence, and `/api/status` names the locale.

- [`495b720`](https://github.com/kechol/kozo/commit/495b72040b5e0daf14e195ba6cda0bb6ce04e0ea) Thanks [@kechol](https://github.com/kechol)! - The factory definition may hold automations: `automations/<name>.md` files with YAML front matter of `version: 1`, a five-field cron `schedule` in kozod's local time, an optional `repository` and an optional `class`, then the request under a `# <title>` heading. In local mode, in each minute the schedule matches while kozod runs, kozod adds the request as an item with the source `automation`, unless an open item of the same repository already has its title. Such an item always waits for your start approval and your plan approval, whatever the autonomy level. A schedule missed while kozod was down is not made up. `kozo admin init` writes one example, `automations/nightly-habit.md`, which asks every night at 03:00 for one swallowed error to be fixed; kozo's template supplies no automation to a definition that lacks the file.

- [`02b6190`](https://github.com/kechol/kozo/commit/02b6190b0b33e2898eb4b7465f555e1c470ee069) Thanks [@kechol](https://github.com/kechol)! - kozod lowers a work class of a repository one autonomy level on its own, never below L1, when a post-merge check finds a defect, or when a human intervened (took the task, committed to its branch at Handoff or sent it back from there) in more than 30 percent of the class's last ten merged diffs since its last demotion. It records `factory.demoted`, notifies you, and applies the lower level until the repository's Charter changes, so editing the Charter, to keep the lower level or to raise it again, ends the demotion. kozod also works out which classes at L2 have had their last 20 merged diffs all autonomous and free of defects, for a promotion to L3 that only you apply in the Charter.

- [`53b65cd`](https://github.com/kechol/kozo/commit/53b65cdd21b17776188d782640bc5cfd3059b67b) Thanks [@kechol](https://github.com/kechol)! - prepare no longer reaches every host. kozod runs a proxy on 127.0.0.1 that tunnels HTTPS only to the package registries (npm, Yarn, PyPI, crates.io, the Go proxy, GitHub's downloads and Playwright's browsers) and to the hosts listed in `factory.yml`'s new `prepare_hosts`, a name or a `*.` suffix; prepare reaches only this machine, as the gates do, with `HTTPS_PROXY` set to the proxy, and kozod reports each host it refused once. A registry mirror must be listed in `prepare_hosts`.

- [`3b13591`](https://github.com/kechol/kozo/commit/3b135918f68334954d8c951660556a0f6938a1d2) Thanks [@kechol](https://github.com/kechol)! - Feature items: when Plan needed? sends a feature to Planning, the plan agent first settles its acceptance criteria, the plan's `done_when`, with you, asking a question whenever a criterion is its own guess that would change what gets built, and the plan waits for your approval only after that. At L3 a single feature task below the high tier is accepted as triage drafted it, like any other class. kozo's template gains `blueprints/feature.yml`, which starts from a test that fails without the change.

- [`6d12eec`](https://github.com/kechol/kozo/commit/6d12eec4f07728fdcca9f4f8cf1eb9d0986ca521) Thanks [@kechol](https://github.com/kechol)! - kozod records the reason of every hold as a message and shows it in the factory's `locale`, in `kozo ls`, `kozo show`, the dashboard and notifications. Event logs are now version 2, and kozod refuses a log of version 1 with that reason; start such a factory again from a new home.

- [`fd4acfd`](https://github.com/kechol/kozo/commit/fd4acfdac5f7f181224f52126a91a94f0fdcda88) Thanks [@kechol](https://github.com/kechol)! - In GitHub mode a repository in `factory.yml` may set `label`, and `kozod` then takes only the open Issues that carry that label as items. A label starting with `kozo:` is refused. An Issue labelled `kozo:paused` still pauses the factory without the label. `kozod` reads the Issue of each open item by its number when the listing misses it, so an item stays followed after its Issue loses the label or falls past the listing's 200 Issues.

- [`6f2f40d`](https://github.com/kechol/kozo/commit/6f2f40d83092c44d7784d01d55a479ec31444cc1) Thanks [@kechol](https://github.com/kechol)! - `kozod` records every edit of a GitHub Issue it takes as the item's new request. Before it writes the new text to `~/.kozo/items/<ref>.md`, it appends `item.edited` with the new title, the SHA-256 of the new request as runs read it, and whether the Issue's author may write. The item's title in `kozo show` and `kozo list` follows the edit.

- [`a793c8c`](https://github.com/kechol/kozo/commit/a793c8cb96d974939774874dcb98b6b5117d9f7a) Thanks [@kechol](https://github.com/kechol)! - kozo's factory template has a migration blueprint, which runs the deep gates and starts from no failing test. A migration's plan is one chain of tasks, each depending on the one before it, and its first task characterizes: it sets `characterize: true` and adds tests that pin the behaviour the migration keeps. kozod refuses a characterization task's diff when it changes anything but test files, and runs its prove in preserve mode.
  
  A plan task may set `codemod` to one shell command, written as one line of printable ASCII characters. kozod, not the agent, runs it in the task's worktree in the gates' sandbox before the task's first implement session, and commits what it changed as kozo; the session finishes the task from there, and review sees the whole diff. A codemod that fails holds the task for attention, and a plan with a codemod always waits for a human's plan approval. The triage and plan agents' instructions describe both fields.
  
  `kozo show <item>` prints a plan that waits for approval: its class, risk tier and approach, and each task with its codemod.

- [`39381df`](https://github.com/kechol/kozo/commit/39381df67d534d6ab04e271cb6da0ce954e19fa1) Thanks [@kechol](https://github.com/kechol)! - kozo's factory template has blueprints for docs, refactor and perf work besides bugfix and deps. None of them starts from a failing test, docs leaves out verify-app, and perf runs at least the full gates.
  
  `kozo prove --preserve` checks a change that keeps behaviour: the tests the diff adds or changes must pass both with and without the non-test changes, and a diff that changes no test passes. kozod runs prove this way for a blueprint that does not reproduce when a human chose the work class, by asking for it or by approving the plan, or when the diff changes only dependency manifests and lockfiles, where it used to skip prove. A class that only the triage session chose still needs a test that fails without the change. The handoff report says which way prove checked the tests.
  
  The implement agent's instructions say that a test added under such a blueprint must pass before the change too.

- [`6f9910d`](https://github.com/kechol/kozo/commit/6f9910de8276e47db6ba60cc0ae792dee59ea030) Thanks [@kechol](https://github.com/kechol)! - What each node of a task's run reports, kozod's notes, defects, raised risk tiers, pauses and demotions are recorded as messages and shown in the factory's `locale`.

- [`91445a5`](https://github.com/kechol/kozo/commit/91445a5305c1b92b3f628b432811474fabd0543d) Thanks [@kechol](https://github.com/kechol)! - `repositories[].locale` in `factory.yml` sets the language of what belongs to a repository, the factory's `locale` when unset: kozod writes the handoff report, the status and question comments, the pull requests and the label descriptions in it, while label names, comment markers and closing keywords stay as they are.

- [`a475629`](https://github.com/kechol/kozo/commit/a4756297f6c7a87766d13fb0e7ee859e9556b6b8) Thanks [@kechol](https://github.com/kechol)! - `.kozo/constraints.yml` may list `services`, commands that start what the gates need and kozo's command sandbox cannot run, such as a database container. `kozod` runs them outside the sandbox in a new worktree before prepare, read from the default branch as prepare is, and holds the task for attention when one fails. `kozo admin install` writes an empty `services` list into the repository template.

- [`def5bdc`](https://github.com/kechol/kozo/commit/def5bdc9fee4c47a58b37110e7d2ae3e705cefd2) Thanks [@kechol](https://github.com/kechol)! - When an implement session calls `kozo_blocked` with the reason `scope`, kozod cancels the task and the open tasks that depend on it, removes their worktrees and branches, and sends the item from Building back to Planning. The plan agent then splits the remaining work from the tasks so far and the stopped task's question and proposed split, and its plan waits for your approval at every autonomy level. - [`0b7ae76`](https://github.com/kechol/kozo/commit/0b7ae76d9881b15de3df2d4ad100db31c5e2406f) Thanks [@kechol](https://github.com/kechol)! - The runs of a task get what the owner said about that task, and about its item from the acceptance of the plan that made the task on. What was said about the item before then shaped the plan and reaches each task through its GOAL and DONE_WHEN, so the review of one task of a split item no longer asks it for the whole item. - [`c24d3e8`](https://github.com/kechol/kozo/commit/c24d3e83fe969d5028067fae2d3da615b4ecd2cc) Thanks [@kechol](https://github.com/kechol)! - `.kozo/constraints.yml` may set `ports`, how many TCP ports each worktree's services and checks take. At a worktree's prepare kozod picks that many free ports on 127.0.0.1 and keeps them for the task's life, and services, prepare, the gates, prove, `kozo_gates` and the check at Complete get them as `KOZO_PORT_1` and on and `KOZO_PORTS`. ### Patch Changes

- [`98d7853`](https://github.com/kechol/kozo/commit/98d785317751ee845d40aa7d5b5dc723846b4ba9) Thanks [@kechol](https://github.com/kechol)! - The constraints gain an optional `generated`, globs of files a tool writes such as lockfiles. diff-guard counts their lines and files apart, reports them on the `KOZO_DIFF_GUARD` line as `generated=<files>files,<lines>lines`, and leaves them out of the Charter's `max_changed_lines` and `max_files`, so a dependency update no longer fails the limits for its lockfile; scope, protected paths, the test checks, review and prove see them as any file. The constraints template shows lockfiles as an example.

- [`7167bf4`](https://github.com/kechol/kozo/commit/7167bf4d05e9183173b58b47af6cf179e3468fb2) Thanks [@kechol](https://github.com/kechol)! - In Japanese, taking a task over is called 自分で作業する, and a task taken over shows 自分で作業中; the dashboard also names the taken hold in English as Taken over.

- [`02fb17f`](https://github.com/kechol/kozo/commit/02fb17f5fa085b2892f84f06f9168cdb9f082249) Thanks [@kechol](https://github.com/kechol)! - The autonomy level that `kozo ls items` and the dashboard show for an item without a requested class is now the one kozod runs it at: the lower of the default level and the drafted class's, where it used to show the drafted class's alone.

- [`84c0837`](https://github.com/kechol/kozo/commit/84c0837c9cf3163ea7ec0045b4c34a0d5e525d45) Thanks [@kechol](https://github.com/kechol)! - Fixes from reviewing the P3 work: `kozo resume` no longer hands back a task you took, which only `kozo return` does, and `kozo return` refuses while the worktree is not on the task branch. The dashboard no longer goes blank when you move from one reference's detail to another's or open a malformed address.

- [`d87204e`](https://github.com/kechol/kozo/commit/d87204eba780cbe290a9a959a167874972144064) Thanks [@kechol](https://github.com/kechol)! - An item whose other tasks were cancelled, by `kozo close --cancel` or by a split again, now completes once its remaining tasks merge, and cancelling one task no longer cancels its whole item while others are open. A post-merge check that fails again after `kozo retry` counts as the same defect and no longer demotes a class a second time. `kozo report` and `kozo admin eval add` report a stopped kozod instead of crashing, a named eval case that cannot be read is an error result rather than the end of the run, and `kozo report --cost` counts a day of a daylight saving change by its own hours.
