## 0.2.0

### Minor Changes

- [`b6657f3`](https://github.com/kechol/kozo/commit/b6657f35d87e702146c9991299ac27c8ae096c8a) Thanks [@kechol](https://github.com/kechol)! - Review now judges a diff also against the repository's AGENTS.md, read from the base branch so the diff cannot change it, and against the plan's approach, so a change in the wrong place, around an existing abstraction or against a written rule is sent back.

## 0.1.0

### Minor Changes

- [`b03a8d5`](https://github.com/kechol/kozo/commit/b03a8d578467aa31bc3da6bc480af288497c37ce) Thanks [@kechol](https://github.com/kechol)! - In a repository whose locale is not English, the agents write their summaries, questions, findings, notes and plans in that language, keeping JSON keys, enum values, paths, code and the conditions kozo gave them as they are; the explorer answers in the factory's locale.

- [`efb3da7`](https://github.com/kechol/kozo/commit/efb3da79f532cfaef5655956e1bdfd37bbdfcb15) Thanks [@kechol](https://github.com/kechol)! - `runtime: cli` in `factory.yml` runs each agent session as `claude -p` instead of through the Agent SDK, with the same guard, sandbox, instructions and kozo tools. Judges and the verify session still run through the Agent SDK.

- [`8dbe593`](https://github.com/kechol/kozo/commit/8dbe59387666a18f3e8f7b0778b142b263d42e5f) Thanks [@kechol](https://github.com/kechol)! - `kozo say --ask <ref> <question>` answers a question about an item, a task or a run without touching the work. kozod gives the explorer agent, a session without tools, the question and its records as untrusted data: the request, the plan or the draft waiting for approval, every task's stage and hold, the subject's last 60 events, and for a task its run reports, decision logs and diff stat. The session is an explorer run of its own with its cost recorded, and kozod refuses an ask while the daily budget is spent. The factory definition may override the explorer's instructions and model in `agents/explorer/agent.md`; kozo's template has one.

- [`4586e42`](https://github.com/kechol/kozo/commit/4586e42b619cbae3ab347297976d90c9da73261e) Thanks [@kechol](https://github.com/kechol)! - `kozo check`, the local API's validation errors and the hold of a refused plan draft word their issues in the factory's `locale`, both kozo's own and the schema library's; the plan agent still reads them in English.

- [`495b720`](https://github.com/kechol/kozo/commit/495b72040b5e0daf14e195ba6cda0bb6ce04e0ea) Thanks [@kechol](https://github.com/kechol)! - The factory definition may hold automations: `automations/<name>.md` files with YAML front matter of `version: 1`, a five-field cron `schedule` in kozod's local time, an optional `repository` and an optional `class`, then the request under a `# <title>` heading. In local mode, in each minute the schedule matches while kozod runs, kozod adds the request as an item with the source `automation`, unless an open item of the same repository already has its title. Such an item always waits for your start approval and your plan approval, whatever the autonomy level. A schedule missed while kozod was down is not made up. `kozo admin init` writes one example, `automations/nightly-habit.md`, which asks every night at 03:00 for one swallowed error to be fixed; kozo's template supplies no automation to a definition that lacks the file.

- [`53b65cd`](https://github.com/kechol/kozo/commit/53b65cdd21b17776188d782640bc5cfd3059b67b) Thanks [@kechol](https://github.com/kechol)! - prepare no longer reaches every host. kozod runs a proxy on 127.0.0.1 that tunnels HTTPS only to the package registries (npm, Yarn, PyPI, crates.io, the Go proxy, GitHub's downloads and Playwright's browsers) and to the hosts listed in `factory.yml`'s new `prepare_hosts`, a name or a `*.` suffix; prepare reaches only this machine, as the gates do, with `HTTPS_PROXY` set to the proxy, and kozod reports each host it refused once. A registry mirror must be listed in `prepare_hosts`.

- [`069827a`](https://github.com/kechol/kozo/commit/069827a7a9ef69626dfdfff2feabcbb151011f76) Thanks [@kechol](https://github.com/kechol)! - kozod confines the diff's commands on Linux with bubblewrap. The system is mounted read-only, the home directory but the paths a command may read, the factory's home, credentials, the user's runtime directory and Docker's socket are hidden, and only the worktree, pnpm's locks and, for prepare, the package caches are writable. Every command but prepare runs in a network namespace of its own, so it reaches only its own loopback and the ports of its worktree (`KOZO_PORTS`) that this machine listens on when it starts, such as the database a repository's services started, which socat relays into it; a port nobody listens on stays the command's own. It sees empty /run and /tmp, so it reaches no Unix socket outside the paths it may write. Install socat for a repository whose gates use such services. A path that may not be written stays unwritten even before it exists. kozod refuses to start when `bwrap` is missing or cannot create namespaces, and `kozo check` reports it.

- [`39381df`](https://github.com/kechol/kozo/commit/39381df67d534d6ab04e271cb6da0ce954e19fa1) Thanks [@kechol](https://github.com/kechol)! - kozo's factory template has blueprints for docs, refactor and perf work besides bugfix and deps. None of them starts from a failing test, docs leaves out verify-app, and perf runs at least the full gates.
  
  `kozo prove --preserve` checks a change that keeps behaviour: the tests the diff adds or changes must pass both with and without the non-test changes, and a diff that changes no test passes. kozod runs prove this way for a blueprint that does not reproduce when a human chose the work class, by asking for it or by approving the plan, or when the diff changes only dependency manifests and lockfiles, where it used to skip prove. A class that only the triage session chose still needs a test that fails without the change. The handoff report says which way prove checked the tests.
  
  The implement agent's instructions say that a test added under such a blueprint must pass before the change too.

- [`b76d326`](https://github.com/kechol/kozo/commit/b76d326ffc4bf794ac757bc98f5990f0ff8f431d) Thanks [@kechol](https://github.com/kechol)! - `kozod` runs the diff's commands in prepare, the gates and prove in kozo's own sandbox, a macOS Seatbelt profile applied through `sandbox-exec`. They read nothing in the home directory but the task's worktree, its repository's git directory, the package caches, the directories of the tools on `PATH` there and those tools' configuration, never `~/.kozo` or a credential path; they write only the task's worktree and a temporary directory of their own, and reach only this machine; prepare may also reach other hosts and write the package managers' caches. Playwright's Chromium runs inside the sandbox. `kozod` refuses to start where it cannot confine these commands, and `kozo check` reports whether it can.

- [`701a67a`](https://github.com/kechol/kozo/commit/701a67a72fe1ae3f9da9a790765ef8eec9b38aa9) Thanks [@kechol](https://github.com/kechol)! - kozod records why an item or a task changed stage and why a run ended as messages, shown in the factory's `locale` in `kozo show -f` and the dashboard's events, and the hold of a task whose review or verify session failed says why in that language too.

### Patch Changes

- [`98d7853`](https://github.com/kechol/kozo/commit/98d785317751ee845d40aa7d5b5dc723846b4ba9) Thanks [@kechol](https://github.com/kechol)! - The constraints gain an optional `generated`, globs of files a tool writes such as lockfiles. diff-guard counts their lines and files apart, reports them on the `KOZO_DIFF_GUARD` line as `generated=<files>files,<lines>lines`, and leaves them out of the Charter's `max_changed_lines` and `max_files`, so a dependency update no longer fails the limits for its lockfile; scope, protected paths, the test checks, review and prove see them as any file. The constraints template shows lockfiles as an example.

- [`76d27d1`](https://github.com/kechol/kozo/commit/76d27d1151fc070810cf02633d925a930aae77d3) Thanks [@kechol](https://github.com/kechol)! - With `runtime: cli`, a hook or tool call whose request or reply is larger than a socket takes at once now arrives whole instead of hanging or failing, text split mid-character is no longer garbled, and a Stop hook the worker cannot answer keeps the agent going instead of letting it stop unchecked. prepare's egress proxy closes a tunnel whose client left or whose token was revoked while it was still opening, stops reading from upstream once the client is gone, passes on everything upstream sent before it closed, and no longer reports a request without kozod's token. `kozo admin eval` stops its egress proxy even when a case throws, an eval teardown that cannot read the base documents no longer replaces the case's result, `kozo issue` opens the Issue with its intake label in one step so a failure leaves no Issue that a retry would open twice, and a kozod start that fails part way stops the proxy and the API server it started.

- [`7a1883f`](https://github.com/kechol/kozo/commit/7a1883f23d28c31641ad2c9a75b9358afbd34236) Thanks [@kechol](https://github.com/kechol)! - The review judge, in kozod and in `kozo review`, now reads at most 400 diff lines of a file and 4,000 in all, and no lockfile; its instructions name each file cut or left out with the lines it adds and removes, so a dependency update no longer fills the session with lines nobody wrote.

- [`7d5b8d4`](https://github.com/kechol/kozo/commit/7d5b8d45d8acffa71c389788215c00d9b6ff7b34) Thanks [@kechol](https://github.com/kechol)! - The review judge now reads lockfiles like any other file, up to 400 lines of each; before, it saw only their names and line counts, so a changed package source or checksum went unread.

- [`83d5c39`](https://github.com/kechol/kozo/commit/83d5c39aca2855faf150b010d4a7174a19348a7e) Thanks [@kechol](https://github.com/kechol)! - On Linux, the sandbox hides each path at its real path and only once, so kozod starts where `/var/run` links to `/run` and Docker's socket exists, as on Ubuntu 24.04, instead of refusing with `Can't create file at /var/run/docker.sock`.

- [`c6d1897`](https://github.com/kechol/kozo/commit/c6d1897696986cc83fe985b6de7d84c1ff34db11) Thanks [@kechol](https://github.com/kechol)! - The verify session's shell, in kozod and in `kozo verify`, can no longer read the factory's home, which holds the API token, except the worktree under test, as a task's shell already could not.

- [`643b9af`](https://github.com/kechol/kozo/commit/643b9af6ce307390523cc56c7e9651f77d13cbd1) Thanks [@kechol](https://github.com/kechol)! - Every command kozod runs for a task, prepare, services, gates, prove, codemods and the agent's `kozo_gates`, now ends within the Charter's `limits.max_minutes`: past it the command and everything it started get SIGTERM, then SIGKILL 10 seconds later, and the command fails with exit code 124 and a line saying it ran out of time. `kozo gates` run by hand has no limit.

- [`dd51433`](https://github.com/kechol/kozo/commit/dd5143305e8539d8b0ea070b4fe96b881eb16c9c) Thanks [@kechol](https://github.com/kechol)! - On macOS, the commands kozod confines, prepare, the gates, prove and the agent's `kozo_gates` included, can no longer connect to kozod's API port; every other port of this machine stays reachable, so a test that starts its own server still works. On Linux the command's network already reaches only the worktree's ports.

- [`e758e8c`](https://github.com/kechol/kozo/commit/e758e8c38d356e22f6d92a7cf35ce0ce677e0154) Thanks [@kechol](https://github.com/kechol)! - In GitHub mode, the `kozo check` workflow that `kozo admin install` opens runs on pushes to the repository's own default branch, instead of a branch named `main` whatever the repository uses.

- [`224bcec`](https://github.com/kechol/kozo/commit/224bcec31249eafdf555f01f67fbe981f8ec2ee6) Thanks [@kechol](https://github.com/kechol)! - Every command kozo confines, prepare, the gates, prove and the agent's `kozo_gates`, may write the three lock directories that pnpm keeps in `/tmp` whatever `TMPDIR` says and change their mode, as pnpm 12.8 does, so pnpm runs inside kozo's command sandbox.

- [`a3380a4`](https://github.com/kechol/kozo/commit/a3380a4770977743b12d3948fed4792ef6887de5) Thanks [@kechol](https://github.com/kechol)! - Fixes in how `kozod` follows work after handoff:
  
  - A task branch with several commits that is squash-merged, as GitHub's default merge does, is recognised as merged.
  - A failing check after the merge of a task that is not its item's last holds the task for attention, and its dependents keep waiting, instead of completing it; `kozo retry` runs the check again.
  - Only GitHub's 404 means a login has no permission; any other failure is retried on the next poll.
  - One Issue that cannot be read or written no longer stops the rest of its repository from being followed.
  - A pull request is followed only for the head that passed final verification, and `kozo retry` after a closed pull request opens a new one.
  - The question comment says that replies on the Issue are not read and to answer with `kozo say`.
  - An Issue closed on GitHub gets its final kozo labels.
  - `kozo check` reads each repository at origin's default branch in GitHub mode, as `kozod` does.
  - A change of `mode` in the factory definition applies when `kozod` starts again.

- [`642c73a`](https://github.com/kechol/kozo/commit/642c73a62bae24f8288569cbaa134056da1b119f) Thanks [@kechol](https://github.com/kechol)! - A command in kozo's command sandbox can no longer remove, rename or replace the worktree, a package cache or pnpm's lock directory it may write, so it cannot turn one into a link that a later run would follow. A root in a directory everyone may write, such as /tmp, counts only as a directory of the factory's user, and a package cache that does not exist is not created inside the sandbox.

- [`956c7a2`](https://github.com/kechol/kozo/commit/956c7a2c499aaeeb6161ae793525e92f0957499d) Thanks [@kechol](https://github.com/kechol)! - `kozo take`, `kozo close`, the cancel of a task and `kozo pause --now` now stop the command a task's run is running, such as its gates or prove, as well as its agent session, and answer once the run has ended as stopped at its node, so the next run resumes there; a human who takes a task no longer has their edits dropped by a check still running in its worktree.
